۰۱چشم‌انداز و ارزش پیشنهادی

چرا این اپ باید وجود داشته باشد و چه چیزی آن را متمایز می‌کند.

بیشتر زبان‌آموزان ایرانی بالاخره با یک آزمون چهارگزینه‌ای روبه‌رو می‌شوند: کنکور، MSRT، EPT، تولیمو، بخش‌هایی از تافل و آیلتس، یا آزمون‌های تعیین سطح آموزشگاه‌ها. اپ‌های بزرگ (Duolingo و مشابه) برای «شروع یادگیری» ساخته شده‌اند، نه برای «تمرین هدفمند تست‌زنی». کتاب‌های تست هم توضیح ندارند، آمار نمی‌دهند و اشتباهات را دوباره جلوی چشم نمی‌آورند.

🎯 تمرین هدفمند

هر سؤال برچسب مهارت، مبحث و سطح CEFR دارد؛ اپ می‌داند کاربر دقیقاً کجا ضعیف است.

💡 توضیح برای هر پاسخ

هر سؤال یک توضیح کوتاه فارسی دارد. تست بدون توضیح فقط حدس‌زدن است، نه یادگیری.

🔁 هیچ اشتباهی گم نمی‌شود

سؤال‌های غلط و نشان‌شده به‌طور خودکار وارد چرخهٔ مرور فاصله‌دار می‌شوند.

📶 آفلاین‌محور

بسته‌های سؤال دانلود می‌شوند؛ با اینترنت ضعیف و قطعی هم اپ کار می‌کند.

اصل طلایی محصول: هستهٔ یادگیری (تمرین، توضیح، بوکمارک، لایتنر پایه) برای همیشه رایگان می‌ماند. پول از «راحتی، عمق و سرعت» درمی‌آید، نه از قفل‌کردن آموزش.

جزئیات طراحی

  • منبع کارت‌ها: لیست‌های آماده (۵۰۴ لغت، لغات کنکور، Academic Word List، لغات سطح‌بندی‌شده CEFR) + لغاتی که کاربر در ریدینگ لمس کرده + لغات سؤال‌های غلط.
  • شکل کارت: روی کارت: لغت + تلفظ + جملهٔ مثال. پشت کارت: معنی فارسی، مترادف، هم‌خانواده. برای تنوع، گاهی کارت به‌صورت چهارگزینه‌ای پرسیده می‌شود (لغت ← معنی یا جای خالی جمله).
  • خودارزیابی: «بلد بودم / بلد نبودم». در حالت چهارگزینه‌ای، نمره خودکار است.
  • سقف روزانه: ۱۰ لغت جدید در روز پیش‌فرض (قابل تنظیم) تا صف مرور منفجر نشود.
  • یادآوری: اعلان محلی ساعت دلخواه کاربر: «۱۸ کارت امروز منتظرند».
موتور زمان‌بندی را از روز اول جدا و قابل تعویض بنویسید. در MVP همان فواصل ثابت ۱-۲-۴-۸-۱۶ کافی است؛ در v2 می‌توان الگوریتم FSRS (الگوریتم Anki) را جایگزین کرد بی‌آنکه ظاهر پنج‌خانه تغییر کند.

خط تولید محتوا

  1. تولید پیش‌نویس: مؤلف انسانی یا هوش مصنوعی با پرامپت استاندارد (سطح، مبحث، نوع سؤال، چهار گزینه با گزینه‌های انحرافی منطقی، توضیح فارسی).
  2. بازبینی انسانی: هر سؤال حداقل یک ویراستار مسلط تأیید می‌کند؛ هیچ سؤال تولیدشده با AI بدون بازبینی منتشر نمی‌شود.
  3. انتشار در پنل ادمین: وضعیت سؤال: پیش‌نویس ← در حال بازبینی ← منتشرشده ← بایگانی.
  4. سنجش کیفیت پس از انتشار: نرخ پاسخ درست، زمان پاسخ و گزارش‌های کاربران. سؤال‌های با «ضریب تمیز» پایین یا گزارش زیاد خودکار پرچم می‌خورند.
  5. کالیبراسیون سختی: سختی واقعی هر سؤال از داده‌های پاسخ کاربران محاسبه و جایگزین سختی حدسی مؤلف می‌شود.
حق تکثیر: سؤال‌ها را از کتاب‌های تست منتشرشده کپی نکنید. سؤال‌های کنکورهای سراسری گذشته معمولاً قابل استفاده‌اند، ولی متن‌های ریدینگ را خودتان بنویسید یا از منابع با مجوز آزاد (مثل ویکی‌پدیا با رعایت CC BY-SA) اقتباس کنید.

۱. تبلیغات (حجم بالا، درآمد کم)

  • تبلیغ جایزه‌دار (Rewarded): تماشا ← یخ‌زدن استریک، دو برابر XP، باز کردن یک آزمون شبیه‌ساز.
  • تبلیغ میان‌صفحه‌ای: فقط بعد از پایان درس، حداکثر هر ۳ درس یک بار. هرگز وسط سؤال.
  • شبکه‌ها: تپسل/ادیوری برای ایران، AdMob برای خارج.

۲. اشتراک «زبانز پلاس» (درآمد اصلی)

  • آمار پیشرفته و نقشهٔ ضعف کامل

  • بسته‌های آفلاین کامل
  • توضیح هوش مصنوعی برای هر سؤال

۳. B2B و فروش موردی

  • پنل آموزشگاه: اشتراک به ازای هر شاگرد؛ معلم تمرین تعیین می‌کند و آمار می‌بیند.
  • بستهٔ آزمون (خرید یک‌باره): مثلاً «۲۰ آزمون کامل MSRT».
  • همکاری با آموزشگاه‌ها و ناشران برای معرفی دوره‌ها (Affiliate).

  • اشتراک روی سرور: وضعیت اشتراک همیشه در بک‌اند نگه داشته شود، نه در اپ؛ تا یک اشتراک روی همهٔ دستگاه‌ها و پلتفرم‌ها کار کند.

قیف تبدیل

پیشنهاد اشتراک فقط در لحظه‌های پرانگیزه نمایش داده شود: پایان آزمون تعیین سطح، بعد از کارنامهٔ هفتگی، قبل از آزمون شبیه‌ساز، و رسیدن به استریک ۷ روزه. یک دورهٔ آزمایشی رایگان ۷ روزه نرخ تبدیل را به‌طور معمول چند برابر می‌کند. هدف واقع‌بینانه: ۲ تا ۴ درصد کاربران فعال ماهانه مشترک شوند.

همگام‌سازی آفلاین

  • سؤال‌ها در قالب بسته‌های نسخه‌دار JSON (مثلاً بر اساس مهارت و سطح) از CDN دانلود و در SQLite ذخیره می‌شوند؛ فقط تغییرات (diff) دوباره دانلود می‌شوند.
  • پاسخ‌ها، بوکمارک‌ها و کارت‌های لایتنر ابتدا محلی ذخیره و به‌صورت دسته‌ای با سرور همگام می‌شوند (outbox pattern).
  • حل تعارض: پاسخ‌ها فقط اضافه می‌شوند (append-only)؛ برای بوکمارک و کارت، «آخرین تغییر برنده است».

۱۰مدل داده

جداول اصلی؛ ساختار سؤال از ابتدا باید برچسب‌گذاری غنی داشته باشد.

// نمونهٔ یک سؤال در بستهٔ JSON
{
  "id": "gr_b1_cond2_0042",
  "skill": "grammar",            // grammar | vocab | reading
  "topic": "conditionals.second",
  "cefr": "B1",
  "difficulty": 0.55,            // 0..1، بعداً از دادهٔ واقعی کالیبره می‌شود
  "exams": ["konkur", "msrt"],
  "passage_id": null,            // برای ریدینگ پر می‌شود
  "stem": "If I ____ more time, I would learn Japanese.",
  "options": ["have", "will have", "had", "would have"],
  "answer": 2,
  "explanation_fa": "شرطی نوع دوم: if + گذشتهٔ ساده، would + فعل ساده.",
  "version": 3
}

🏠 خانه

دکمهٔ بزرگ «درس امروز»، تعداد کارت‌های لایتنر امروز، استریک، میان‌بر «مرور اشتباهات».

📚 تمرین

انتخاب مهارت ← مبحث ← سطح؛ آزمون‌های شبیه‌ساز؛ بوکمارک‌ها و دفتر اشتباهات.

🗃️ لغات

جعبهٔ لایتنر پنج‌خانه، لیست‌های لغت، جستجو و افزودن لغت دلخواه.

📊 من

آمار، لیگ، مدال‌ها، اشتراک، تنظیمات (یادآور، تم، هدف روزانه).

اولین تجربه (Onboarding) — زیر ۶۰ ثانیه تا اولین سؤال

  1. «برای چه زبان می‌خوانی؟» (کنکور / MSRT-EPT / آیلتس-تافل / عمومی)
  2. «روزی چقدر وقت داری؟» (۵ / ۱۰ / ۲۰ دقیقه)
  3. آزمون تعیین سطح یا «از مبتدی شروع کن»
  4. نتیجه و اولین درس — ثبت‌نام بعد از اولین درس پیشنهاد می‌شود، نه قبل از آن.

اصول UX

  • متن سؤال انگلیسی چپ‌چین (LTR)، رابط کاربری راست‌چین (RTL)؛ هر دو باید دقیق تست شوند.
  • بازخورد فوری با رنگ و آیکون (برای کاربران کوررنگ)؛ لرزش ملایم (haptic).
  • اندازهٔ فونت قابل تنظیم، اهداف لمسی حداقل ۴۸ پیکسل، تم تاریک.
